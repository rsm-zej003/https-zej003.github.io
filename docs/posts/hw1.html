Introduction

Every website that cares about conversions has a “call to action” — a button, a line of text, a prompt that nudges visitors toward doing something. On my site, that something is signing up for a newsletter. The question I want to answer is simple: does the exact wording of that prompt matter?

To find out, I set up an A/B test comparing two versions of the sign-up prompt:

  • CTA A: “Sign up for our newsletter here!”
  • CTA B: “Stay up to date by signing up!”

In an A/B test, visitors are randomly assigned to see one of the two versions. Half the visitors see CTA A; the other half see CTA B. By comparing sign-up rates between the two groups, we can estimate whether one version genuinely outperforms the other — or whether any observed difference is just noise.

This post walks through the full statistical machinery behind that inference: how we model the data, how we estimate the effect, and how we decide whether the evidence is strong enough to declare a winner. Along the way, we’ll simulate data and use it to demonstrate three foundational results from classical statistics — the Law of Large Numbers, the Bootstrap, and the Central Limit Theorem — before connecting them to a formal hypothesis test and a regression model. We’ll also explore one of the most common mistakes practitioners make: peeking at results too early.

The A/B Test as a Statistical Problem

Each visitor who lands on the page either signs up or doesn’t. That binary outcome — 1 for sign-up, 0 for no sign-up — is naturally modeled as a draw from a Bernoulli distribution. If a visitor is shown CTA A, their outcome \(X_i^A\) is drawn from \(\text{Bernoulli}(\pi_A)\), where \(\pi_A\) is the true (unknown) probability that a visitor shown CTA A will sign up. Similarly for CTA B with parameter \(\pi_B\).

The quantity we care about is the difference in sign-up rates:

\[\theta = \pi_A - \pi_B\]

If \(\theta > 0\), CTA A performs better; if \(\theta < 0\), CTA B is superior; if \(\theta = 0\), the two are equivalent. Our job is to estimate \(\theta\) and assess how confident we can be in that estimate.

The natural estimator is the difference in sample proportions:

\[\hat\theta = \bar{X}_A - \bar{X}_B = \hat\pi_A - \hat\pi_B\]

Since each observation is 0 or 1, the sample mean is exactly the proportion of visitors who signed up. This estimator is unbiased — on average, it equals the true \(\theta\) — but it is noisy, and how noisy depends on sample size. The rest of this post is about understanding and quantifying that noise.

Simulating Data

In the real world, \(\pi_A\) and \(\pi_B\) are unknown — estimating them is the whole point of running the experiment. But for the purpose of this exercise, we’ll set the true values ourselves. This lets us verify that our statistical methods are working correctly: we know the truth, so we can check whether our procedures recover it.

We’ll assume:

  • \(\pi_A = 0.22\) (22% of visitors shown CTA A sign up)
  • \(\pi_B = 0.18\) (18% of visitors shown CTA B sign up)
  • True effect: \(\theta = \pi_A - \pi_B = 0.04\)

We simulate 1,000 visitors per group — 2,000 total.

import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
import matplotlib.gridspec as gridspec
import seaborn as sns
from scipy import stats

rng = np.random.default_rng(42)

pi_A = 0.22
pi_B = 0.18
n    = 1000

group_A = rng.binomial(1, pi_A, n)
group_B = rng.binomial(1, pi_B, n)

theta_hat = group_A.mean() - group_B.mean()
print(f"Observed θ̂ = {theta_hat:.4f}  (true θ = 0.04)")
Observed θ̂ = 0.0250  (true θ = 0.04)

Our observed estimate is close to the true value of 0.04. But how much should we trust a single estimate from 1,000 observations? Let’s find out.

The Law of Large Numbers

The Law of Large Numbers (LLN) states that as the sample size grows, the sample mean converges to the true population mean. For our estimator, this means \(\hat\theta = \bar{X}_A - \bar{X}_B\) will get closer and closer to the true \(\theta = 0.04\) as we collect more data. The LLN is the theoretical guarantee that our estimator is consistent — given enough data, it will eventually pin down the truth.

The chart below makes this concrete. For each observation \(k\) from 1 to 1,000, we compute the running average of the element-wise differences \((X_i^A - X_i^B)\). At \(k = 1\) we only have one pair of observations; the estimate is highly unstable. As \(k\) grows, the running average settles down toward the true value.

diffs   = group_A - group_B
cum_avg = np.cumsum(diffs) / np.arange(1, n + 1)

This is the LLN in action: more data means less noise and more reliable estimates.

Bootstrap Standard Errors

Knowing that our estimator will eventually converge is reassuring, but it doesn’t tell us how uncertain we are right now, with the 1,000 observations we actually have. For that, we need a standard error — a measure of how much \(\hat\theta\) would vary if we repeated the experiment many times.

The bootstrap gives us a data-driven way to estimate this variability without needing a closed-form formula. The idea is elegant: treat your observed data as a stand-in for the full population, and simulate repeated experiments by resampling from it with replacement. Each resample yields a new estimate \(\hat\theta^*\); the standard deviation across many such estimates approximates the true standard error.

B = 1000
boot_ests = np.array([
    rng.choice(group_A, n, replace=True).mean() -
    rng.choice(group_B, n, replace=True).mean()
    for _ in range(B)
])

se_boot = boot_ests.std()

# Analytical SE
pi_hat_A = group_A.mean()
pi_hat_B = group_B.mean()
se_analytic = np.sqrt(
    pi_hat_A * (1 - pi_hat_A) / n +
    pi_hat_B * (1 - pi_hat_B) / n
)

ci_lower = theta_hat - 1.96 * se_boot
ci_upper = theta_hat + 1.96 * se_boot

print(f"Bootstrap SE : {se_boot:.5f}")
print(f"Analytical SE: {se_analytic:.5f}")
print(f"95% CI: [{ci_lower:.4f}, {ci_upper:.4f}]")

The two methods agree closely — the bootstrap SE is np.float64(0.01859) and the analytical formula gives np.float64(0.01825). This agreement validates the bootstrap approach. In settings where an analytical formula doesn’t exist (e.g., for medians or ratios), the bootstrap is indispensable.

Using the bootstrap standard error, our 95% confidence interval for \(\theta\) is:

\[\hat\theta \pm 1.96 \times \widehat{SE} = [np.float64(-0.0114),\ np.float64(0.0614)]\]

Because this interval excludes zero, it suggests that CTA A’s advantage over CTA B is unlikely to be due to chance alone — though we’ll formalize that claim in the hypothesis testing section.

The Central Limit Theorem

The bootstrap tells us about the variability of \(\hat\theta\) for a fixed dataset. The Central Limit Theorem (CLT) gives us something deeper: regardless of the shape of the underlying data distribution (here, Bernoulli), the sampling distribution of \(\hat\theta\) becomes approximately Normal as sample size grows.

This is remarkable. Our raw data is binary — every observation is a 0 or 1. There’s nothing bell-shaped about it. Yet aggregate enough of those 0s and 1s into a sample mean, and the mean’s distribution looks Normal. We simulate 1,000 experiments at four different sample sizes to see this in action.

sample_sizes = [25, 50, 100, 500]
sims = 1000

clt_results = {}
for s in sample_sizes:
    ests = np.array([
        rng.binomial(1, pi_A, s).mean() - rng.binomial(1, pi_B, s).mean()
        for _ in range(sims)
    ])
    clt_results[s] = ests

At \(n = 25\), the distribution is lumpy and irregular — with so few Bernoulli draws the sample means can only take a limited number of discrete values. By \(n = 100\), the bell shape is clearly emerging, and at \(n = 500\) the distribution is strikingly Normal, tightly centered on the true value of 0.04.

Two things to notice: (1) as \(n\) grows the distribution narrows — this is the LLN again; (2) the shape converges to Normal regardless of the binary underlying data — this is the CLT. Together, these two results form the statistical backbone of classical hypothesis testing.

Hypothesis Testing

The CLT has given us a critical piece of information: for large enough samples, \(\hat\theta\) is approximately normally distributed. Under the null hypothesis \(H_0: \theta = 0\) (the two CTAs perform identically), \(\hat\theta\) is approximately \(N(0, \text{SE}^2)\).

This lets us standardize our estimate into a test statistic:

\[z = \frac{\hat\theta - 0}{SE(\hat\theta)}\]

The logic runs as follows:

  1. By the CLT, \(\hat\theta \sim N(\theta, SE^2)\) for large \(n\).
  2. Under \(H_0\), \(\theta = 0\), so \(\hat\theta \sim N(0, SE^2)\).
  3. Dividing by \(SE\) gives \(z \sim N(0, 1)\) — a standard Normal whose distribution we know exactly.
  4. We compute the p-value: the probability of observing \(|z|\) this large or larger if \(H_0\) were true.

A note on terminology: this is often called a “t-test” in software output. Technically, the t-distribution arises when data are Normal and the variance is estimated from the data. Our data are Bernoulli (not Normal), so there is no exact t-distribution result here. The CLT gives us approximate Normality, making this formally a z-test. For large samples the t and z distributions are nearly identical — the distinction has little practical impact, but it matters conceptually.

z_stat  = theta_hat / se_analytic
p_value = 2 * stats.norm.sf(abs(z_stat))

print(f"θ̂        = {theta_hat:.4f}")
print(f"SE       = {se_analytic:.5f}")
print(f"z-stat   = {z_stat:.3f}")
print(f"p-value  = {p_value:.4f}")

With a p-value of np.float64(0.1708), we reject the null hypothesis at the \(\alpha = 0.05\) level. If the two CTAs truly performed identically, the probability of observing a difference as large as ours in a sample of 1,000 is only 17.08%. The data provide reasonably strong evidence that CTA A outperforms CTA B.

The T-Test as a Regression

There is a neat algebraic equivalence that is easy to miss: the two-sample test we just ran is mathematically identical to a simple linear regression. The regression framework is far more flexible — it handles multiple treatment arms, control variables, and interactions with the same machinery.

The setup: stack all 2,000 observations into one dataset. Define \(Y_i\) as the sign-up outcome (0 or 1) and \(D_i\) as a group indicator (\(D_i = 1\) for CTA A, \(D_i = 0\) for CTA B). Then fit:

\[Y_i = \beta_0 + \beta_1 D_i + \varepsilon_i\]

The coefficients have clean interpretations:

  • \(\beta_0 = \pi_B\) — the sign-up rate for the control group (CTA B).
  • \(\beta_1 = \pi_A - \pi_B = \theta\) — exactly the quantity we’ve been estimating all along.
from scipy.stats import t as t_dist

Y = np.concatenate([group_A, group_B]).astype(float)
D = np.concatenate([np.ones(n), np.zeros(n)]).astype(float)

X = np.column_stack([np.ones(2 * n, dtype=float), D])
beta_hat = np.linalg.lstsq(X, Y, rcond=None)[0]
beta0, beta1 = beta_hat

residuals = Y - X @ beta_hat
sigma2 = float((residuals ** 2).sum()) / (2 * n - 2)
XtX_inv = np.linalg.inv(X.T @ X)
cov_beta = sigma2 * XtX_inv
se_beta1 = np.sqrt(cov_beta[1, 1])
t_stat = beta1 / se_beta1
p_reg  = 2 * t_dist.sf(abs(t_stat), df=2 * n - 2)

print(f"β̂₁ = {beta1:.4f}  SE = {se_beta1:.5f}  t = {t_stat:.3f}  p = {p_reg:.4f}")
β̂₁ = 0.0250  SE = 0.01826  t = 1.369  p = 0.1712
OLS Regression: Y ~ D
Coefficient on the treatment indicator D
Term Estimate Std. Error t-statistic p-value
D (CTA A indicator) 0.025 0.01826 1.369 0.1712

The coefficient estimate \(\hat\beta_1 =\) np.float64(0.025) is numerically identical to \(\hat\theta\) from the two-sample test. The t-statistic and p-value also match closely. The small difference in standard errors arises because OLS pools variance across groups, while the two-sample formula estimates separate variances — a distinction that matters little when group sizes are equal and large.

The practical payoff: whenever your experiment gets more complicated — multiple treatment arms, pre-experiment covariates, subgroup interactions — you don’t need a new test. You extend the regression.

The Problem with Peeking

So far we’ve assumed that we collect all 1,000 observations per group and then run a single test. In practice, that’s rarely what happens. Stakeholders are impatient. Dashboards get refreshed constantly. The temptation to check results early — and stop the moment something looks significant — is overwhelming.

This practice is called peeking, and it’s statistically dangerous.

Here’s why. A single test at \(\alpha = 0.05\) has a 5% false positive rate: if \(H_0\) is true, we’ll incorrectly reject it 5% of the time. But every time we peek and run a test, we get another chance at a false positive. Across 10 peeks, the cumulative probability of at least one false rejection is far higher than 5%.

To quantify this, we simulate a world where the null hypothesis is true — both CTAs have a 20% sign-up rate (\(\theta = 0\)) — and ask: how often does peeking lead us to a wrong conclusion?

rng2 = np.random.default_rng(123)
pi_null     = 0.20
n_max       = 1000
peek_points = np.arange(100, n_max + 1, 100)
n_sims      = 10_000

def run_experiment(rng):
    A = rng.binomial(1, pi_null, n_max)
    B = rng.binomial(1, pi_null, n_max)
    for k in peek_points:
        d    = A[:k].mean() - B[:k].mean()
        pa   = A[:k].mean(); pb = B[:k].mean()
        se   = np.sqrt(pa*(1-pa)/k + pb*(1-pb)/k)
        if se == 0:
            continue
        p = 2 * stats.norm.sf(abs(d / se))
        if p < 0.05:
            return True
    return False

false_pos_rate = np.mean([run_experiment(rng2) for _ in range(n_sims)])
print(f"False positive rate with peeking: {false_pos_rate:.1%}")
False positive rate with peeking: 19.7%
Peeking Inflates the False Positive Rate
Simulated under H₀: θ = 0 (10,000 experiments)
Scenario False Positive Rate
Single test at end (α = 0.05) 5.0%
Peek after every 100 obs (10 peeks) 19.7%

The results are stark. With a single end-of-experiment test, the false positive rate is the intended 5%. With 10 peeks at \(\alpha = 0.05\) each time, the false positive rate balloons to roughly 19.7% — more than np.float64(3.9)× higher than advertised.

In practical terms: if your team stops the experiment the moment a dashboard turns green, you’ll declare a winner roughly one in 5 times even when there is genuinely no difference. Decisions made this way are decisions based on noise.

The fix is not to never look at data — it’s to either (a) pre-commit to a single end-of-experiment analysis, (b) apply a multiple-testing correction such as Bonferroni, or (c) adopt a sequential testing framework like the mSPRT, which is designed to allow continuous monitoring without inflating error rates. Classical frequentist statistics was built around fixed-sample designs; the peeking problem is a reminder to respect that assumption.
